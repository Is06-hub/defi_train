## 1. الهدف والموقف الإرغونومي الصارم (Purpose & Ergonomic Stance)

يحدد هذا الدليل مسار العمل الهندسي لفريق الواجهة الأمامية (Frontend) لبناء تطبيق **PainVisual**. تم تصميم الواجهة للاستجابة المباشرة لتحدي **Hair'gonomie**، وتجسيد الموقف الإرغونومي الجذري:

> **«الألم يُرى ولا يُوصف بالكلمات»**

### المبادئ التوجيهية لتجربة المريض:
- **حظر الاستمارات النصية الطويلة (Zero-Form Paradigm):** إلغاء حقول الإدخال الكتابية المعقدة والاستعاضة عنها باللمس المباشر، السحب، والتلوين.
- **تخفيض الحمل الذهني (Zero Cognitive Load):** المريض يمر بلحظة ألم وقلق وتفاوت في القدرة التعبيرية؛ لذا يجب أن تكون كل حركة بديهية لا تتطلب أي تدريب مسبق.
- **سرعة الاستجابة اللمسية (Instant Tactile Feedback):** معالجة كافة لمسات الأصابع محلياً على الشاشة بمعدل 60 إطاراً في الثانية (60 FPS) دون أي تأخير شبكي (Latency-free).

## 2. نطاق مسؤولية فريق الواجهة (Frontend Team Ownership)

يمتلك فريق الواجهة الأمامية المسؤولية الحصرية عن:
- شجرة مجلد العميل: `frontend/src/**` (المبنية بواسطة React 19 و Vite).
- مكتبة مكونات التفاعل اللمسي والأصول التشريحية: `frontend/src/components/**` و `frontend/src/assets/anatomy/**`.
- مخزن الحالة التفاعلي للجلسة: `frontend/src/store/usePainSessionStore.ts`.
- عميل الاتصال الموحد بالخلفية: `frontend/src/services/apiClient.ts`.
- اختبارات الواجهة، وسلوك المكونات وإمكانية الوصول: `frontend/tests/**`.

## 3. بيئة التشغيل والمكدس التقني (Runtime & Tech Stack)

```bash
# تشغيل بيئة تطوير الواجهة الأمامية محلياً
cd frontend
npm run dev
```

- **الواجهة تعمل افتراضياً على:** `http://localhost:5173`
- **نقطة اتصال الـ REST API الخلفية:** `http://localhost:5000/v1`

### المكونات البرمجية المعتمدة:
- **نواة التطبيق:** React 19 + TypeScript (نمط التحقق الصارم `strict: true`).
- **محرك البناء:** Vite 5+ فائق السرعة.
- **التنسيق والتصميم:** Tailwind CSS v3.4+ مع دعم التباين العالي والمتغيرات السلسة.
- **إدارة الحالة:** Zustand (خفيف الوزن وسريع، متوافق تماماً مع التحديث المتزامن للـ Canvas).
- **الأيقونات والرموز:** Lucide-React للأيقونات العامة، وأيقونات مخصصة بدقة SVG لطبيعة الألم والوضعيات.
- **تسجيل الصوت:** Web Audio API و MediaRecorder لتسجيل وضغط الملاحظة الصوتية (Opus/WebM).
- **التصدير البصري:** HTML5 Canvas API لتصيير لقطة مجمعة من خريطة الجسم فورياً.

## 4. القواعد الصارمة لتطوير الواجهة (Core Frontend Rules)

1. **الاعتماد الحصري على عميل الـ API الموحد (`apiClient.ts`):** يُمنع منعاً باتاً استدعاء `fetch` أو `axios` المباشر داخل مكونات الصفحات.
2. **التعامل مع الحالات الأربع لكل شاشة:** يجب أن تدعم كل شاشة الحالات الأساسية: التحميل (`loading`)، الخطأ اللمسي (`error`)، الحالة الفارغة (`empty`)، ونجاح الإدخال (`success`).
3. **أولوية الهواتف الذكية (Mobile-First Architecture):** يجب أن تُصمم كل شاشة لتعمل بكفاءة فائقة على شاشات الهواتف من مقاس 360px وما فوق، وتتسع تلقائياً لتناسب شاشات الأجهزة اللوحية والحواسيب.
4. **أحجام لمسية ملائمة للألم (Pain-Adapted Touch Targets):** يجب ألا يقل حجم أي عنصر قابل للمس (زر، موضع ألم، أيقونة) عن **48×48 بكسل** منعاً للأخطاء الحركية للمريض المتألم.
5. **منع تسرب منطق الأعمال:** التحقق الأولي للبيانات يجري بالواجهة للمساعدة فقط، بينما يبقى الخادم هو المرجع النهائي لصحة العمليات.

## 5. استراتيجية البيانات الموكية والربط التدريجي (Mocking & Swap Rule)

لضمان تقدم فريق الواجهة بالتوازي مع الخلفية دون انتظار:
1. يتم إنشاء ملف موكي شامل `frontend/src/services/mockApi.ts` يطابق بنسبة 100% عقد الواجهات في [api-contract.md](file:///c:/Users/MO/Desktop/ai-drive/New%20files/api-contract.md).
2. تعتمد الموكات على الغلاف القياسي `{ success, data, error, meta }` وتستخدم معرفات UUID صالحة.
3. التبديل من الموك إلى الخادم الحقيقي يتم بتغيير متغير واحد في ملف البيئة:
   ```env
   VITE_USE_MOCKS=false
   VITE_API_BASE_URL=http://localhost:5000/v1
   ```
دون الحاجة لتعديل سطر واحد في مكونات الشاشات السبع.

## 6. تنفيذ الشاشات السبع خطوة بخطوة (Step-by-Step 7 Screens Execution)

### الشاشة 1: شاشة الترحيب وبدء الوصف (`Screen1_Welcome.tsx`)
- **الهدف الإرغونومي:** استقبال المريض، طمأنته، وإتاحة الدخول الفوري دون نموذج تسجيل أو طلب بيانات معقدة.
- **العناصر والمكونات:**
  - شعار التطبيق وموقفه الإرغونومي: «الألم يُرى ولا يُوصف بالكلمات».
  - رسم بياني متحرك خفيف يوضح حركة إصبع يلمس الجسد (SVG Animation).
  - زر لمسي عريض وبارز: **«بدء الوصف»** (ارتفاع 60px، مساحة لمس مريحة).
  - مفتاح اختيار لغة بديهي وبسيط (عربي / فرنسي).
- **التكامل مع الـ API:**
  - استدعاء `POST /v1/sessions` وتخزين `sessionId` و `sessionToken` في مخزن Zustand.
  - الانتقال الفوري والتلقائي إلى الشاشة 2.

### الشاشة 2: تحديد مكان الألم — أمامي/خلفي وتعدد المواضع (`Screen2_Location.tsx` - F1)
- **الهدف الإرغونومي:** تمكين المريض من الإشارة المباشرة لموضع ألمه على مجسم تشريحي.
- **العناصر والمكونات:**
  - **مسطح الجسم التشريحي (`BodyCanvas.tsx`):** رسم متجه دقيق للجسم (SVG) مقسم تشريحياً لمناطق محددة (الرأس، الرقبة، الظهر العلوي، أسفل الظهر، الأطراف، إلخ).
  - **مفتاح التبديل المنظوري (`ViewToggle.tsx`):** زر لمسي كبير للتبديل الفوري بين **«العرض الأمامي (Front)»** و **«العرض الخلفي (Back)»**.
  - **النقاط التفاعلية (Pain Pins):** لمس أي منطقة يولد دائرة تركيزية نابضة ويسجل الإحداثيات النسبية `(x, y)`.
  - **دعم تعدد المواضع:** إمكانية تحديد أكثر من موضع ألم مع عداد لمسي صغير، والنقر على الموضع مرة ثانية لحذفه إن لزم.
  - **شريط التنقل السفلي (`NavigationFooter.tsx`):** زر «التالي» (سهم واضح لا يحتاج قراءة) وزر «رجوع».
- **التكامل مع الـ API:**
  - إرسال `PUT /v1/pain-records/:id/location` بقائمة المواضع والإحداثيات.

### الشاشة 3: تحديد اتجاه ومسار انتشار الألم (`Screen3_Radiation.tsx` - F2)
- **الهدف الإرغونومي:** تجسيد الشعور بامتداد الوجع وانتقاله فيزيائياً عبر سحب الإصبع.
- **العناصر والمكونات:**
  - إبراز موضع الألم المحدد في الشاشة السابقة كنقطة انطلاق مضيئة.
  - تعليمة بصرية إرشادية طافية: «اسحب إصبعك باتجاه امتداد الألم».
  - **محرك سحب المتجهات (`RadiationVectorLayer.tsx`):** عند وضع الإصبع على الموضع وسحبه، يُرسم مسار متجه متدرج ديناميكي ينتهي بسهم شفاف موجه باتجاه السحب (منحنى بيزيير تربيعي).
  - زر تخطٍ لمسي سريع: «الألم في مكانه ولا يمتد» للمرضى ذوي الألم الموضعي غير المنتشر.
- **التكامل مع الـ API:**
  - إرسال `PUT /v1/pain-records/:id/radiation`.

### الشاشة 4: تحديد شدة الألم والتلوين الموضعي (`Screen4_Intensity.tsx` - F3)
- **الهدف الإرغونومي:** الاستغناء عن المقاييس الرقمية المجهدة (مثل مقياس 1-10 النمطي) لصالح التدرج اللوني الطبيعي الحسي.
- **العناصر والمكونات:**
  - **طبقة التلوين اللمسي (`IntensityPaintLayer.tsx`):** تلوين موضع الألم بتدرج دافئ:
    - لون فاتح خافت $\rightarrow$ ألم بسيط ومحتمل.
    - لون برتقالي دافئ $\rightarrow$ ألم متوسط ومزعج.
    - لون قرمزي/عنابي داكن $\rightarrow$ ألم حاد وشديد لا يطاق.
  - **عجلة/شريط التلوين التناظري (`IntensityTouchSlider.tsx`):** شريط تمرير عريض تحت الجسم يتجاوب مع حركة الإبهام ويغير تدرج اللون ومساحة التوهج على موضع الألم في الزمن الحقيقي.
- **التكامل مع الـ API:**
  - إرسال `PUT /v1/pain-records/:id/intensity` بمستوى الشدة والرمز اللوني `colorHex`.

### الشاشة 5: اختيار طبيعة الألم وسحب الرموز (`Screen5_Nature.tsx` - F4)
- **الهدف الإرغونومي:** ترجمة الإحساس النوعي للألم عبر رموز تعبيرية استعارية بديهية تُسحب وتُفلت مباشرة على الجسم.
- **العناصر والمكونات:**
  - **صينية الرموز السفلية (`SensationTray.tsx`):** شريط أفقي قابل للسحب يضم الرموز الخمسة المعتمدة:
    - 🔥 **حرقان (Burning):** شعلة نار دافئة.
    - ⚡ **وخز / كهرباء (Pricking/Electric):** صاعقة وخزية حادة.
    - 🔨 **نبض / خفقان (Throbbing):** أمواج نبضية دورية.
    - 🔪 **طعن حاد (Stabbing):** سهم أو رأس حاد ومركز.
    - 🪨 **ثقل / عصر (Heavy Ache):** كتلة ضغط ثقيلة.
  - **التفاعل بالسحب والإفلات (Touch Drag & Drop):** يلمس المريض الرمز ويسحبه بإصبعه، وعند الاقتراب من موضع الألم، يلتصق الرمز بالموضع تلقائياً عبر مغناطيسية لمسية (Snap-to-Target).

## 7. معمارية إدارة الحالة المحلية ومخزن الجلسة (State Management with Zustand)

تعتمد الواجهة مخزناً مركزياً موحداً وسريعاً (`usePainSessionStore.ts`) يدعم حفظ التغييرات واستعادتها محلياً:

```typescript
// usePainSessionStore.ts
import { create } from 'zustand';
import { persist } from 'zustand/middleware';

interface PainLocation {
  locationId: string;
  bodyPart: string;
  bodyView: 'front' | 'back';
  coordinates: { x: number; y: number; radius: number };
  intensity?: { level: number; colorHex: string; gradientSpread: number };
  radiation?: { hasRadiation: boolean; endCoordinates?: { x: number; y: number }; pathVector?: string };
  sensations: Array<{ type: string; iconId: string; placedAt: { x: number; y: number } }>;
}

interface PainSessionState {
  sessionId: string | null;
  sessionToken: string | null;
  activeView: 'front' | 'back';
  locations: PainLocation[];
  timing: { onsetHours: number[]; isConstant: boolean; frequency: string };
  movements: Array<{ movementId: string; affectedLocationId: string; severity: string }>;
  audioDuration: number;
  reportData: any | null;
  
  // Actions
  startSession: (token: string, id: string) => void;
  toggleView: () => void;
  addOrUpdateLocation: (location: Partial<PainLocation>) => void;
  removeLocation: (locationId: string) => void;
  setIntensity: (locationId: string, level: number, colorHex: string) => void;
  setRadiation: (locationId: string, endX: number, endY: number, path: string) => void;
  attachSensation: (locationId: string, sensation: any) => void;
  setTiming: (timing: any) => void;
  setMovements: (movements: any[]) => void;
  resetSession: () => void;
}
```

## 8. محرك التفاعل اللمسي ورسم المتجهات (Touch & Canvas Interaction Engine)

1. **التعامل مع شاشات اللمس (Pointer Events Normalization):**
   - استخدام أحداث المؤشر الموحدة `onPointerDown`, `onPointerMove`, `onPointerUp` لضمان استجابة موحدة سواء تم التفاعل بإصبع اليد، قلم إلكتروني (Stylus)، أو مؤشر الفأرة.
2. **منع الارتجاف اللمسي (Touch Jitter & Scroll Prevention):**
   - تطبيق خاصية CSS `touch-action: none` على مسطح الجسم لمنع تمرير الصفحة غير المقصود أثناء تلوين أو سحب مسار الألم.
3. **حساب منحنيات الانتشار (Bézier Smoothing):**
   - حساب مسار الانتشار ديناميكياً أثناء السحب وتوليد كود الـ SVG:
     ```typescript
     function calculateBezierPath(startX: number, startY: number, endX: number, endY: number): string {
       const midX = (startX + endX) / 2 + (endY - startY) * 0.15;
       const midY = (startY + endY) / 2 - (endX - startX) * 0.15;
       return `M ${startX} ${startY} Q ${midX} ${midY} ${endX} ${endY}`;
     }
     ```

## 9. معايير التجاوبية وإمكانية الوصول الشامل (Responsiveness & Accessibility WCAG AA)

- **التباين اللوني (Color Contrast):** جميع ألوان النصوص والأيقونات تحقق نسبة تباين لا تقل عن 4.5:1 وفق معايير WCAG 2.1 AA.
- **التصميم الخالي من الاعتماد على اللون فقط:** كل مستوى شدة لوني يدعمه مؤشر رمزي ومساحة انتشار مرئية لتمكين المستخدمين المصابين بعمى الألوان من التعبير بدقة.
- **الملاحة بدون كتابة:** النصوص في التطبيق مقتصرة على التوجيه الإرشادي القصير، وتعتمد الواجهة بالكامل على استعارات بصرية ملموسة.
- **الأهداف اللمسية:** جميع الأزرار والرموز مصممة بحجم لا يقل عن 48 بكسل مع مسافات فاصلة تمنع الضغط الخاطئ.
